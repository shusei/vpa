# 發布後真機快速檢查

每次發布完成後，以正式 HTTPS 網址在至少一台 iPhone Safari 與一台 Android Chrome 執行以下檢查。GitHub Pages 工作流程會先跑完整自動測試，部署後也會確認 `assets/vendor/ffmpeg/ffmpeg-core.wasm` 可正常下載。

## 裝置資訊

記錄裝置型號、作業系統版本、瀏覽器版本、測試網址與測試時間；若失敗，保留畫面錄影及遠端除錯主控台訊息。

## 錄音與即時音高

1. 重新整理頁面，確認起始模式為 Quick。
2. 在 Quick 完成一次「錄音 → 停止 → 結果」，不要重新整理。
3. 切換到 Professional，再開始第二次錄音；不要手動捲到圖表，確認 `#pitchWrap` 緊接錄音控制區、位於上一輪結果之前，Hz 數字持續更新且曲線有繪製。僅確認元素不是 `display:none` 不足以驗收。
4. 接著連續執行至少十輪「錄音、停止、播放、暫停」，每輪都確認圖表與下一輪可恢復。
5. 測試途中切到背景再返回一次，並旋轉螢幕一次，確認錄音與音高區塊仍可恢復。
6. 以相同序列分別檢查淺色與深色主題，並確認橫向／直向皆無水平 overflow。
7. 若任何一輪失敗，以同一正式網址加上 `?vpaAudioDebug=1` 重跑並下載 JSON；診斷檔不得包含或上傳錄音內容。

這組步驟必須在 iPhone Safari 與 Android Chrome 各完成一次。Playwright WebKit 或合成麥克風通過，不能取代實機結果。

## 影片上傳

1. 上傳一般 MP4 與手機拍攝的 MOV/HEVC，確認分析與播放都能完成。
2. 上傳一段超過三分鐘的影片，確認會顯示長檔提示並完成分析。
3. 上傳無音軌影片與損壞檔案，確認顯示可理解的錯誤，之後仍能上傳正常檔案。
4. 確認測試期間沒有頁面重載、白畫面、持續轉圈或瀏覽器記憶體警告。
